**第十课：业务知识库 RAG 使用教程**

> 本文按课程阶段讲解；请在仓库根目录执行命令。安装与当前功能以[仓库 README](../README.md)为准，早期章节中的简化流程不代表最终实现。

这份教程对应 `.` 当前的网页 Agent。RAG 是 Retrieval-Augmented Generation，中文通常叫“检索增强生成”：先查找与你的问题有关的资料，再把查到的原文交给聊天模型，让它据此回答。

你日常只需要做两件事：把业务资料保存进 `knowledge` 文件夹，然后在聊天网页中提问。生成向量、检索和传递片段由程序处理。资料不会因此变成聊天模型永久学会的知识。

**1. 打开聊天页面，先用现有资料试一次**

打开 [订单客服网页](http://127.0.0.1:8000/)。页面已经能用时，无须重复启动服务；打不开时，在 PowerShell 执行：

```powershell
# 在仓库根目录运行
.\.venv\Scripts\python.exe -X utf8 .\07_api_server.py
```

保持服务进程运行。首次使用请按仓库 README 配置聊天模型；Embedding 是可选项，缺少模型文件时会回退到关键词检索。

点击“新对话”，输入：

> O1001 现在是什么状态？还能修改收货地址吗？请查阅资料并说明依据。

这句话需要两种信息：订单现在怎样，以及改地址的规则是什么。Agent 可以调用 `get_order` 查询订单，再调用 `search_knowledge` 检索政策；也可能在同一次模型响应中提出这两个工具调用，顺序不固定。

目前的演示订单 O1001 是已发货，示例配送政策规定已发货订单不能由助手直接修改地址，应联系人工协调物流。回答应结合这两点，并说明依据是示例政策。实际回答的措辞可能不同。

当前已有资料：

| 文件 | 包含内容 |
|---|---|
| [示例配送政策](../knowledge/delivery.md) | 物流进度、修改地址、联系方式与送达偏好 |
| [示例售后政策](../knowledge/after_sales.md) | 退货条件、质量问题、退货运费、退款处理时间 |

这两份文件都是功能演示资料，不代表真实商家的政策。

**2. 查看回答依据，判断是否真的用到了资料**

检索过程中，页面会显示“正在查阅业务资料…”。回复完成后，如果有原文片段交给模型，回答下方会出现“检索参考资料 · N 段”。

展开它可以看到资料标题、章节和原文片段；点击标题，可以打开来源全文。你可以逐句对照回答，检查具体条件是否有依据。例如，“可以申请退货”和“已经退款成功”是不同的事情，当前工具只负责查询资料，不能执行退款、退货审批或修改地址。

“检索参考资料”表示这一轮曾提供给模型的片段，不代表每一段都支持最终结论。检索可能找到主题相近但不足以回答的资料，模型仍需要判断其适用性。

再试两个问题：

| 输入的问题 | 重点观察 |
|---|---|
| 东西刚收到就坏了，我要怎么处理？请查阅售后政策。 | 能否找到“商品损坏与质量问题”，并依据原文说明所需材料 |
| 寄到境外的关税由谁承担？只按已有资料回答，没规定就说明。 | 当前资料没有这项规定，应说明无法确认，不能补出一条政策 |

**3. 添加一份你自己的资料**

打开 [knowledge 文件夹](../knowledge)。可以放 UTF-8 编码的 `.md` 或 `.txt` 文件，也支持普通子文件夹。当前没有网页上传入口；PDF、Word 和图片不会被自动读取，需要先整理成 Markdown 或纯文本。

练习时，可以手动新建 `.\knowledge\pickup_demo.md`，保存下面这段文字。教程不会自动把它加入知识库：

```markdown
# 示例自提政策

仅用于本地功能测试，不代表真实业务承诺。

## 自提开放时间（示例）
演示自提点周二至周六 10:00—18:00 开放，周日和周一不开放。

## 自提所需凭证（示例）
领取商品需要订单号和自提码。没有收到自提码时，请联系人工确认。
助手不能生成自提码，也不能安排自提预约。
```

保存后，在网页新建一个测试对话，问：

> 按示例自提政策，星期天能去取货吗？取货需要带什么？

预期依据是“周日不开放”和“需要订单号、自提码”，来源应包含《示例自提政策》。不需要重启服务，也不需要手动生成向量。

资料尽量按主题分开，标题要明确，一个小节说明一条完整规则，把条件、例外和处理方式写在一起。程序按章节切片，关键例外离规则太远时，单次检索可能只取到其中一段。

接入真实业务时，用经确认的正式文件替换相应示例，把不再适用的旧版本移出 `knowledge`。程序不会根据文件名或“版本日期”自动裁定哪条政策优先；互相冲突的现行资料需要由你整理。

**4. 验证资料更新和历史来源**

完成上面的练习后，把测试文件中的开放时间改成：

```text
演示自提点周二至周日 10:00—18:00 开放，周一不开放。
```

保存，再问：

> 请重新查阅当前的示例自提政策，星期天现在能去取货吗？

下一次检索会读取修改后的文件。规则要求模型回答政策时重新查资料，旧对话中的回答不能代替现行政策。对照新回答的参考片段，确认它引用了修改后的文字。

历史回答会保留当时实际提供给模型的参考片段。由于文件已经更新，点击历史回答中的旧来源链接会提示版本变化；它不会悄悄用新版全文冒充旧版。当前系统没有保存每份文件的完整历史版本，旧依据以聊天里保存的片段为准。

练习结束后，可以把测试文件移出 `knowledge`。之后的检索不再把它当作当前资料，但已保存的旧回答和参考片段仍然存在。想单独验证“移出后查不到”，请开一个新对话，避免旧聊天内容影响观察。

**5. 一次提问背后发生了什么**

```text
你：O1001 已发货，还能改地址吗？
                  ↓
聊天模型读取问题、当前上下文和工具说明
                  ↓
模型提出工具调用，例如：
get_order(order_id="O1001")
search_knowledge(query="已发货 修改收货地址")
                  ↓
Python 查询订单，并读取 knowledge 中的资料
                  ↓
资料按章节切片 → 关键词匹配 + 本地向量语义检索 → 合并排序
                  ↓
选出的原文片段与订单结果作为 tool 消息加入上下文
                  ↓
聊天模型读取工具结果，生成回答并标注依据
                  ↓
页面显示回答与参考资料，成功完成的回合保存到 SQLite
```

这里有两个不同的决定。聊天模型决定“要不要调用哪个工具、用什么检索词”；Python 的检索算法决定“哪些资料片段排在前面”。模型不直接浏览电脑里的文件，也不能通过工具参数指定任意文件路径。

当前使用 `tool_choice="auto"`，并通过工具描述和系统规则要求政策问题先查资料。这是对模型的行为要求，仍可能出现漏查或查询不准确；是否出现检索状态和参考片段，是你检查本轮行为的入口。

**6. Embedding 和语义检索在这里怎么用**

例如，用户说“东西一到手就是坏的”，资料写的是“收到商品后发现破损、缺件或无法正常使用”。字面未必完全相同，但意思有关。

本地 Embedding 模型会把查询和资料片段分别转换成数字向量。程序比较向量的余弦相似度，找出语义接近的候选，再与关键词匹配的候选合并排序。相似度是相关性信号，不是政策正确性或回答可信度的概率。

下面是当前代码的实现参数，帮助你理解实际行为；日常使用不需要手动设置：

| 环节 | 当前实现 |
|---|---|
| 切片 | 先按 Markdown 标题分节，再切为最多 240 个字符的片段；同节相邻完整窗口重叠 40 个字符 |
| 关键词匹配 | 用检索词匹配标题、章节与正文；当前没有自动中文分词 |
| 语义匹配 | 本地 `BAAI/bge-small-zh-v1.5`，余弦相似度至少 0.45 的片段进入语义候选 |
| 合并排序 | 用 RRF 合并两路排名，公式为各路 `1 / (60 + 名次)` 相加 |
| 结果数量 | 一次知识库检索最多返回 3 个不相互重叠的片段 |
| 结果预算 | 检索结果先限制在估算 900 tokens 内，还可能因整轮上下文预算而进一步减少 |

这些数值是本项目的实现选择，不是 RAG 必须遵守的通用参数。240 个字符也不等于 240 tokens。

当前没有独立的向量数据库：每次检索读取当前文件并切片，在内存中比较候选。片段向量按内容哈希缓存；命中缓存就复用，没有缓存或内容变了才重新计算。重启后内存向量缓存需要重新建立。

**7. 哪些步骤调用模型、需要联网**

| 步骤 | 使用什么 | 是否联网 |
|---|---|---|
| 首次准备 Embedding | 下载本地模型文件 | 需要；当前机器已准备好 |
| 生成查询、片段向量 | 本机 CPU 运行 Embedding 模型 | 推理本身不需要 |
| 匹配、排序、选择片段 | Python 算法 | 不需要 |
| 判断工具调用、生成最终回答 | 配置的 DeepSeek 聊天模型 | 需要，产生模型请求用量 |
| 长对话触发滚动摘要 | 聊天模型生成摘要 | 触发时需要额外请求 |

一次简单的工具问答通常是“请求模型选择工具 → 本地执行工具 → 再请求模型回答”，但请求次数并不固定，多次检索或摘要可能增加请求。

虽然 Embedding 在本机运行，选中的知识库片段仍会作为上下文发给配置的聊天模型。准备资料时，应按这个实际数据流选择可以交给模型处理的内容。

**8. 它与聊天历史、滚动摘要有什么关系**

| 能力 | 负责的问题 |
|---|---|
| `get_order` | 这笔订单现在是什么状态？当前项目查询的是模拟订单数据 |
| `search_knowledge` | 业务规则是什么？从 `knowledge` 中查当前资料，供各个会话共用 |
| `search_history` | 我在这段对话里以前说过什么？只查当前会话保存的原文 |
| 滚动摘要与近期完整回合 | 让模型在 token 预算内理解对话进展 |

RAG 检索到的原文作为工具结果加入当前回合，和系统规则、摘要、近期对话、当前问题一起受到 token 预算限制。不会把整个知识库一次性发给模型，也不会因为增加 RAG 就改回固定传入多少轮历史。

当前每个用户回合中，知识库检索与历史检索合计最多完成 3 次检索；每次最多返回 3 个知识库片段，不代表每个问题一定会返回 3 段。

**9. 遇到问题时怎么检查**

| 现象 | 检查方式 |
|---|---|
| 新资料没有被找到 | 确认放在项目的 `knowledge` 中，文件已保存，后缀确实是 `.md` 或 `.txt`，编码为 UTF-8；不是隐藏文件或以点开头的目录。再用资料标题和核心关键词提问 |
| 换一种说法就找不到 | 打开 [健康检查](http://127.0.0.1:8000/api/health)，查看 `semantic_status`；`ready` 表示本地 Embedding 已加载，不保证每个问题都能检索到相关片段 |
| `semantic_status` 是 `unavailable` | 当前会回退到关键词。若本地模型文件缺失，可执行下面的下载命令后重启服务；若仍失败，检查依赖与服务日志 |
| `semantic_status` 是 `disabled` | 检查服务配置是否选择了关键词模式。当前 `AGENT_HISTORY_SEARCH=keywords` 会同时关闭历史和知识库的语义检索；改回 `hybrid` 后需要重启服务 |
| 资料读取报错 | 检查 UTF-8 编码、文件权限和大小限制。当前最多 100 份资料，单份 128 KiB，总计 512 KiB；不是只忽略出错文件后继续查 |
| 回答没有参考资料 | 检查是否调用过知识库、是否有结果，以及预算是否容得下片段。可以明确要求“请查阅资料并说明依据”，但仍需核对最终引用 |
| 查到的内容与问题无关 | 相似不等于适用；把问题问具体，整理清楚标题、条件和例外，并查看实际返回的原文 |
| 点击旧来源提示已更新或已移除 | 文件已经变化；在原回答下方查看保存的旧片段，重新提问获取当前规则 |

仅在需要准备或补全本地模型时运行，命令会联网下载文件：

```powershell
# 在仓库根目录运行
.\.venv\Scripts\python.exe -X utf8 .\local_embeddings.py
```

**10. 想继续看代码，可以按这个顺序**

| 文件 | 重点阅读 |
|---|---|
| [knowledge_base.py](../knowledge_base.py) | `KNOWLEDGE_TOOL` 是模型看到的工具说明；`_documents()` 读资料，`_chunks()` 切片，`search()` 检索 |
| [local_embeddings.py](../local_embeddings.py) | `LocalEmbeddings.scores()` 生成向量、使用缓存、计算相似度 |
| [api_app.py](../api_app.py) | 创建知识库并绑定目录，`knowledge_reader()` 将检索交给工作线程执行 |
| [agent_service.py](../agent_service.py) | `stream_agent()` 接收工具调用，把检索结果放进下一次模型请求，并保留来源 |

建议先完成“提问 → 查看原文 → 添加测试资料 → 修改后重新检索”这组操作，再从 `knowledge_base.py` 读起，对照你刚才看到的页面行为。
